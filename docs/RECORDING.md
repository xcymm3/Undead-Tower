# 实机试玩录制

## 当前 rogue 分支：手枪肉鸽试玩

启动本地开发服务，并按下方说明准备完整 FFmpeg 后，执行：

```powershell
node scripts/record-rogue-playthrough.mjs
```

脚本选择正式模式的手枪，持续战斗、换弹，在清波后停留展示三选一升级并确认，直至正常失败。录制包含倒计时、原始游戏音效和音乐、两秒失败特写及五秒结算页。自动瞄准读取开发诊断中的敌人投影，射击和升级经过游戏正常输入处理；不会改写血量、弹药、波数或成绩，因此这段自动操作演示不代表真人的难度水平。

只开一个独立的 1280×720 Chrome 页面，复用下方的 30 FPS H.264 / AAC 采集流程。单波超过 100 秒或波间检查总时长超过七分钟会停止并报错，不人为制造结算。输出位于 `recordings/<时间>/Undead-Tower-rogue-playthrough.mp4`，同目录记录升级、新敌人首次出现、换弹和最终成绩等时间点。录像与原始素材不提交 Git，不修改 EXE。

## 历史版本：正式模式六枪试玩

以下六枪脚本对应肉鸽改版前的连续生存规则；当前 rogue 分支请使用上面的脚本。

录制脚本使用独立 Chrome 会话，直接发送鼠标移动、左键、数字键、滚轮和 R 键。只读诊断用于选择目标投影和核对演示覆盖，不直接扣除敌人血量、增加弹药、改变刷新规则或写入游戏成绩。成绩由正常失败流程产生，并保留在隔离会话中。

## 运行

先启动 `npm run dev`。录制需要本机 Chrome 和包含 H.264 / AAC 的完整 FFmpeg；Playwright 自带的精简 FFmpeg 不满足此要求。

可在忽略的输出目录内单独安装录制工具，不改变游戏依赖：

```powershell
npm install --prefix recordings/tools --no-save --package-lock=false ffmpeg-static@5.3.0
node scripts/record-playthrough.mjs
```

也可以通过 `FFMPEG_PATH` 指向已有完整 FFmpeg，`GAME_URL` 指向已有开发服务。脚本依赖开发版的只读诊断接口，不能对生产版 EXE 使用。

同时只启动一个 1280×720 游戏页面。画面通过 Chrome screencast 采集，并按帧时间编码为 30 FPS H.264；声音从游戏主音量出口复制，按开始时间与画面同步，输出 AAC 立体声音轨。保留连续对局、两秒失败特写和四秒结算展示，不快进对局、不剪接枪械演示。开始录制后的五分钟上限用于资源保护，超时会报错，不伪造游戏结束。

输出位于 `recordings/<时间>/`：

- `Undead-Tower-six-weapons.mp4`：最终可播放视频。
- `recording.json`：六枪射击/换弹覆盖、时间点与实际成绩。
- `events.json`：操作阶段日志；`result.png`：实际结算截图。
- `picture.mp4`、`game-audio.webm`：合成前的原始画面和声音。

视频、原始录制和工具下载不提交 Git，也不随游戏或 EXE 打包。
