# Undead Tower 立项说明

立项日期：2026-09-03。版本：0.1.0。首阶段：M0「第一发子弹」。

## 项目定位

一款固定哨位的 3D 生存射击游戏。玩家驻守哨塔，武器覆盖眼前的防区，镜头只能在固定朝向的小范围内以较强阻尼转动。后续游戏张力来自前方威胁、装填时机与防线管理，而不是自由移动和大范围转身。

美术参考《未转变者》的方块化轮廓、低面数几何和简洁色块，所有模型均为本项目原创程序化模型，不导入该游戏资产。首个场景使用松林、路障、检查站、巡逻车、哨塔护栏构成明确空间层次。

## M0 交付范围

1. 建立可运行、可构建、可继续扩展的项目。
2. 第一人称右手持枪，手臂与枪械为真实 3D 几何。
3. 鼠标自由准星；枪口指向鼠标对应的世界位置。
4. 镜头有可感知的小幅阻尼跟随，但朝向绝不无限累积。
5. 左键射击，包含火光、枪口照明、曳光、抛壳、后坐平移、命中碎屑与枪声。
6. 用可复位的人形靶闭合验收流程；包含弹药、换弹、暂停、设置与错误提示。
7. 立项文档、操作说明、自动化测试和实际画面证据。

M0 不加入玩家移动、敌人追击、基地养成或商店。这些系统会使首阶段的操控验收变得不清晰，先确保持枪、瞄准和镜头规则稳定。

## 核心体验契约

| 项目 | 规则 |
| --- | --- |
| 坐标 | 世界前方为 -Z；相机位于 (0, 4.8, 9) |
| 基准俯角 | -0.105 rad，略俯视公路 |
| 水平转动 | 基准方向附近 ±4° |
| 垂直转动 | 基准方向附近 ±2.5° |
| 输入模型 | 绝对屏幕坐标归一化到 [-1, 1]，不使用位移累加 |
| 镜头跟随 | 指数阻尼，默认 λ=2.4，可在 1～5 间调整，越小阻尼越强 |
| 武器朝向 | 本地 -Z 对准世界瞄准点；镜头和枪械分别更新 |
| 发射规则 | 30 发弹匣、约 522 RPM、1.55 秒换弹 |
| 弹道 | Hitscan；准星求点后从枪口复核遮挡 |
| 目标 | 身体 50、头部 100 伤害；生命 100；击倒后 3 秒复位 |

近距离护栏可能挡住枪口，此时命中实际遮挡物；不允许为了对齐准星而穿过墙体。装填时武器降低并倾斜，期间不能开火。

## 技术方案

采用 React + TypeScript + Vite + Three.js。选择浏览器原型是为了快速试玩、方便迭代操控，无需先安装游戏编辑器或桌面运行时。

- React 只处理菜单、设置和低频 HUD 刷新；帧循环由 Three.js 类管理。
- 纯函数实现视角约束和枪口四元数，独立状态机处理武器装填与冷却。
- 场景、枪械、音频分离，后续可以逐模块替换正式资源。
- 第一阶段无需完整物理引擎。射线测试完成命中与遮挡，轻量粒子模拟完成碎屑和弹壳。
- 场景仅在可见且必要时绘制，限制帧率、像素总量、阴影更新频率和粒子上限。
- 开发模式提供只读 `window.__undeadTower.snapshot()` 以便验收；生产构建不暴露该接口。

## 项目风险与应对

- 固定朝向需要精准定位：屏幕准星与实际枪口射线使用共同世界点，并对四角瞄准自动验证。
- 大阻尼可能让人误以为镜头没动：画面环境应有缓慢视差，HUD 显示小幅角度，设置可调整阻尼但不能扩大转向范围。
- 高分辨率和多个测试浏览器会增加系统负载：渲染有上限，测试串行；实测吞吐只代表对应设备，不承诺所有设备达到 60 FPS。
- 手臂容易被第一人称透视裁掉：桌面截图单独检查枪身、手部与准星的布局。
