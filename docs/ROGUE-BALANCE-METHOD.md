# 六枪波次平衡方法

`npm run balance:rogue -- --output <scratch>/rogue-balance.json --assert` 运行冻结的正式矩阵：六枪、regular/skilled/expert、24 个固定种子、60/30 FPS，共 864 局，单进程顺序执行。需要先完成数值调试与真实回放校准；脚本存在不代表平衡通过。

## 代理输入

| 水平 | 命中概率 | 命中后爆头概率 | 半自动间隔 | 换目标延迟 | 空匣反应 | 技能反应 |
| --- | --- | --- | --- | --- | --- | --- |
| regular | 0.70 | 0.45 | 0.20 s | 0.22 s | 0.25 s | 0.35 s |
| skilled | 0.88 | 0.75 | 0.14 s | 0.12 s | 0.12 s | 0.20 s |
| expert | 0.96 | 0.92 | 0.115 s | 0.05 s | 0.06 s | 0.10 s |

`scripts/rogue-agent.ts` 只接受当前观察，不读取未来敌人、随机数或卡片。自动枪瞄准后持续尝试，生产枪械决定实际射速；半自动还受表中点击间隔约束。目标按预计抵达时间和稳定 ID 选择，维持到死亡或失去可见性，切换重新支付瞄准延迟。目标 ETA 使用距离突破边界的直线距离除以当前移动速度，是未包含绕路/拥挤的下界。

技能条件为至少三个可见活敌人，或某个可见敌人距突破边界不超过 12 米；满足后再等待技能反应时间，换弹/阻塞期间不激活。波间终止技能，保留冷却，装满弹匣并清理未完成装填。模拟省略波间 UI 等待，不推进有效时钟。

种子为 `42031 + i * 177`，`i=0..23`。regular 偶数索引使用随机卡片，奇数索引依次优先伤害、射速、技能冷却、技能持续、弹容、装填、暴击率、暴击伤害；同类别按稳定 ID。其他水平先选最高稀有度，再用相同优先级。抽牌、升级决策、命中、暴击、出生位置和巫师瞬移使用分离的确定性随机流。

## 生产规则与近似边界

模拟实际调用 `Encounter`、`Arsenal/Firearm`、`ActiveSkill`、`weaponStats/skillStats`、`hitWithShot`、`waveEnemies/waveRate`、`CrowdMovement/Navigation`、游走/突进/号令/狂暴、击退/减速及巫师瞬移规则。`sceneRules.ts` 的出生筛选和 `combat.ts` 的散弹方向被正式游戏与模拟共同调用。逐局机器输出同时保留十类出生/击杀组成、四类特殊行为事件计数、巫师瞬移次数和暴击计数，供模型与真实回放逐项对照；事件计数是生产 `Encounter` 发出的行为结果，不是代理自行推断。

`createWorld` 生成同一份原始场景与导航障碍；无 DOM 时只省略招牌纹理，招牌几何保留。`StaticCollision` 将场景实例分解后建立包围体树，用实际几何求交，包围盒仅用于筛选。敌人仍使用实际 `ZombieField` 方块碰撞。双持逐枪口、散弹逐弹丸、贯穿按距离/世界阻挡、护甲破坏后碰撞同步均调用实际规则。

模型省略渲染和枪械动画，使用无后坐枪口位置；镜头按上一帧指针位置调用生产有限阻尼。代理把目标头/身体中心投影为有界屏幕指针；射击时先取摄像机射线最近表面，再从枪口检测碰撞。失败瞄准投影敌人上空位置并按屏幕边界裁切，不能事后把本应命中的子弹折算掉。左轮在非射击帧也更新锁定，和游戏逐帧锁定保持一致。死眼技能仍会按生产规则覆盖错误瞄准，因此技能期间实际命中率可能高于基础假设。实体遮挡、弹丸散布和部件命中也可能令实际爆头比例与请求比例不同。报告分别保留请求命中/爆头、实际命中扳机/含爆头扳机和技能次数/有效持续时间。

这些近似必须由六枪各 regular seed 42031、expert seed 42208 的 12 局真实静默回放校准：完整通过波数绝对差中位数不超过 2，最大不超过 5，进入 50 波判断一致。模型输出本身不证明这个门槛，也不是玩家实测。

## 统计与运行

每局自然失败或达到 60 个完整通过波/3600 秒有效时间时结束。上限退出记 `censored`，不会伪装成自然失败。`completed >= 49` 计进入第 50 波，`completed >= 50` 计通过第 50 波。所有逐局记录保留武器、水平、FPS、seed、策略、完整波数、失败波、耗时、命中/爆头/暴击计数、技能计数、敌人构成、特殊事件、瞬移次数与逐波构筑。

按武器/水平/FPS 及合并组报告均值、中位数、P10/P90、最小最大值、早败率、进入/通过 50 波率与删失。regular 另拆分两种升级策略。分位数为排序后 `floor((n-1)*p)`；均值 95% 区间采用 `mean ± 1.96 * sd / sqrt(n)` 正态近似，50 波率使用 Wilson 95% 区间。样本缺失、重复、普通组删失、高水平到 50 波前删失和任一冻结数值门槛不满足时，`--assert` 非零退出。

快速诊断示例：

```powershell
npm run balance:rogue -- --quick --profile regular --output "$env:DEADLINE_CARL_OUTPUT_DIR/quick.json"
```

`--quick` 只使用第一个 seed、60 FPS。`--weapon rifle,pistol` 和 `--profile regular` 可限定诊断范围；这些报告不可能通过正式矩阵门槛。`--assert` 在诊断模式下预期非零退出。

长矩阵每完成一局追加到输出旁的 `.runs.jsonl`，并写 `.manifest.json` 记录源码/配置哈希及取样参数。可用 `--max-runs 100` 分段，随后用同一输出和参数加 `--resume` 继续。未加 `--resume` 时总是从头重新运行；fresh verification 应从新的 scratch 输出开始。源码、配置或取样参数变化会拒绝续跑，不能把旧配置样本混进新矩阵。部分矩阵即便报告 `formal: true` 也会因不足 864 局而失败。

可用 `--seed-count 4 --fps 60 --profile regular` 做固定种子前缀的多种子预调；显式使用这些诊断过滤器永远标记非正式，不能用来通过 864 局门槛。manifest 包含 seedCount 和 FPS 列表，参数不同不能续跑。Windows 如果系统 `npm.ps1` 引用了不存在的全局 npm，请使用同一 Node 安装目录中的 `npm.cmd`；本轮实际用 `C:/Program Files/nodejs/npm.cmd` 完成单元与构建。

## iteration 008：路径公平性与未完成的调参

早败轨迹揭示了一个固定视野缺陷：边缘出生的铁桶、宽体绕障的巨人会在离开视野后继续突破。先内收林地入口，再让生产与模拟共享 `fairApproach` 筛选导航路径；已覆盖实际场景中原先有问题的巨人入口和保留的正面宽通道。该筛选不改变已存在敌人的移动与刷怪配额。当前参数见六枪设计说明，所有新参数仍需重新完成真实配对与完整矩阵。

本轮当前重型编队配置的 regular / seed 42031 / 60 FPS 诊断：步枪 completed 29，P90 22，手枪 22，狙击 21；这些为单种子，不能推断正式均值。霰弹枪在 32 伤害 / 18 mrad 时 completed 7，尝试 48 伤害 / 12 mrad 后 completed 6，仍然过早。最新轨迹显示巫师在第 7 波以 162.24 剩余生命突破；它会在一发散弹的首颗非致命命中后立即瞬移，后续弹丸因此通常落空。应继续检查巫师的单次扳机结算与瞬移后的可射击路线，而不是只扩大霰弹伤害。左轮长局诊断本轮中断，未获得结果；所有中断局都不计自然失败或完成样本。没有调整代理概率、升级策略或验收门槛。

为控制验证成本，模拟用 `ZombieField.syncCollision` 按射线候选惰性生成姿态，仍调用渲染相同的部件变换与 Float32 实例矩阵。十类敌人、多姿态、碎甲、狂暴和多条射线的逐命中结果与普通 sync 完全一致。步枪/P90/手枪三局在改造前后的逐局 JSON 全字段一致。CPU 采样的主要热点为导航 clear、静态碰撞树、射线包围盒和拥挤避让；静态树增加 far 范围裁剪，遮挡查询发现真实三角形命中后立即返回。其后步枪完整 29 波逐局数据仍与优化前逐字段一致，实际耗时 37.4 秒。该优化不会以包围盒替代真实几何命中。

本轮最终 136/136 单元、类型/生产构建和 diff 检查通过。864 局矩阵、当前配置 12 局实际回放、剩余技能边界/压力/视觉/全 E2E 尚未完成；先前 iteration 007 的配对结果不能证明这些新参数。单个长局成本明显高于早期 5–10 波诊断，需要重新估算三次正式矩阵的时间，不能按旧的六局 10.4 秒外推。

## 静默实际回放入口

`npm run test:rogue:replay -- --output <scratch>/replay --assert` 自动创建独立端口 5177 的 Vite `replay` 模式服务器，以及一个 headless、强制静音的 Chrome 实例。六枪按 regular seed 42031、expert seed 42208 顺序运行；脚本结束时关闭浏览器及自己启动的服务器。每局调用正式 Game 更新、真实鼠标/键盘事件、动画枪口、世界/敌人碰撞、技能及升级路径。自动枪在取得目标后保持左键，由 Game 连发；概率政策在每个可开火步长选择真实指针落点。

专用控制器仅在 `DEV && MODE === 'replay'` 时挂载，普通开发页和生产页不提供回放入口。它只支持固定 30/60 FPS 步进、指定本局 seed/开局武器、观察与正常升级确认，没有直接设置波数、血量或伤害的接口。倒计时正常步进，暂停和失焦不推进有效时间。每 180 步绘制一帧，截图只能证明该采样时刻；视觉动效仍需另行验收。隔离 browser context 保存测试成绩，不接触用户本机存储。

回放先运行六枪生命周期集成检查（倒计时、机械动作排队/换弹拒绝右键、重复按下、暂停恢复、失焦冻结、新局清空），然后逐局输出独立 JSON、结果图与汇总 `report.json`。汇总保留源码哈希、配置哈希、命中/爆头比例、技能次数/时长与出生种类。`--weapon`、`--profile`、`--max-waves`、`--max-seconds` 仅供明确标为非正式的诊断，不能通过完整协议检查。
